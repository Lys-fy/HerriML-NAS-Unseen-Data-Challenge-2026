# v11.3 - Evolutionary heterogeneous search (path beyond the hill-climb)

> **Status:** IDEA / parked (gated on v11.2 results) | **Topic:** replace v11.2's greedy coordinate-descent hill-climb with a population-based EVOLUTIONARY search over the same heterogeneous micro-macro space, keeping verify-before-adopt for the commit. The next rung up in search power, when v11.2 proves there is headroom to chase. | **Related:** [[v11.2]], [[v11]], [[EGNAS]], [[2022 - BLOX Macro NAS Benchmark]], [[DARTS Family]]

## The progression

- **[[v11]]** - incremental: v10 core + gated macro-attention + ensemble. Safe.
- **[[v11.2]]** - EGNAS-style **hill-climb** (coordinate descent: depth -> per-stage op -> width) over a heterogeneous, deep, cross-family op space, every move verified. Genuine search, but **greedy**.
- **v11.3 (this note)** - **evolutionary** search over the *same* space. Drops the greedy limitation; gated on v11.2 showing the heterogeneous space beats v10.

## Why evolution, after the hill-climb

v11.2's hill-climb is honest and cheap but **greedy / local**:
- It optimises one axis at a time (depth, then ops, then width), so it cannot see **joint** interactions (e.g. a depth that only pays off *with* a particular per-stage op pattern).
- It commits to one trajectory and cannot **recombine** good sub-architectures or **escape a local optimum**.

Evolutionary search fixes both: it holds a **population**, explores the joint space globally, and recombines/mutates the best. BLOX found **regularised evolution among the strongest conventional methods** on the macro-NAS benchmark, and its prescription -- search broadly, trust only the fully-trained finalists -- is exactly our verify discipline.

## The design

A **regularised-evolution** loop over heterogeneous (op-per-stage x depth x width) architectures, with our multi-fidelity verify:

- **Population (size P):** seeded from the v10-route arch + the v11.2 hill-climb winner + random heterogeneous archs (so we start no worse than what we already have).
- **Each cycle:**
  1. **Sample** a tournament subset; pick the best by a **cheap-screen** score (short-train) -- selection pressure only, never a commit.
  2. **Mutate** the parent to make a child. Operators: swap a stage's op (micro), **add / remove a layer** (macro depth, including going deeper), change width (macro), and optionally **graft** a stage-block from another strong member (recombination).
  3. **Cheap-screen** the child, add it to the population; **regularised** = remove the OLDEST member (age-based), which prevents over-exploiting one lineage and keeps exploring.
- **Commit (the reliability gate):** periodically (or at the end) take the top-K by cheap-screen and **full-train + verify** them; adopt the best **only if it beats the v10-route arch beyond noise** -- identical to v11.2's top-level rule. The evolution's cheap-screen drives *selection*; the verify drives the *commit*. Proxy-wall confined to selection, never to adoption.

## Multi-fidelity, hardware-agnostic (inherited from v11.2)

Cheap-screen = epoch-based short-train (portable, fair); full-train verify = the committed decision. Deployment self-sizes the population / generations to the wall-clock budget on whatever GPU it lands on (calibrate one epoch, then fit) -- same principle as [[v11.2]].

## Cost / when it is worth it

- Population-based search is **many more evaluations** than a hill-climb -> genuinely **cluster-era** (A100s), parallelisable across the population.
- Only worth building if **v11.2 shows the heterogeneous space has real headroom over v10** (e.g. closes a chunk of the CIFARTile / Chesseract gaps). If the hill-climb already extracts most of it, evolution's extra cost buys little. If the hill-climb gets stuck in obvious local optima, evolution is the unlock.

## Risks

- **Cost** (the main one) -> cluster-only.
- **Selection under a noisy cheap-screen** -> evolution may chase short-train mirages in *selection*; mitigated because the commit is verify-gated, and regularised (age-based) evolution is robust to occasional bad selections.
- **Mutation operator design** (especially depth add/remove on a net with fixed downsampling) needs care so children stay valid (reuse `plan_downsamples`).

## Carried forward

Gated entirely on [[v11.2]]. Build only if the hill-climb both (a) beats v10 and (b) looks local-optimum-limited.
