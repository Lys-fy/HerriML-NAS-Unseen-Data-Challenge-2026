# v9 - searched dilated backbone

> **Status:** seed-42 verdict (search net-negative vs the fixed backbone) | **Dates:** 2026-06-10/11 | **Code dir:** `baselines/v9` | **Total adj:** **+52.4** (s42, vs the fixed TCN-2d +59.2) | **Deep-dive:** [[Pipeline v1-v7 - Aug Probe]], [[TCN Backbone Excursion]]

## What was done

Put the **dilated TCN-2d block inside the v8 search** (depth/width tuned per dataset, micro off, EGNAS_DMAX=8). The aim was to confirm whether searching the dilated backbone holds or beats the fixed-backbone result.

## Why (motivation; what changed from v8)

The [[TCN Backbone Excursion]] showed that a *fixed* 2-D dilated-conv backbone (TCN-2d) beats the entire searched conv backbone (**+59.2 vs +48.2** at seed 42), winning 6 / tying 4 / losing 3. The receptive field, not the op micro-choice, is the lever. v9 tests whether wrapping that backbone in the existing depth/width search adds anything.

## Tested

v9 seed 42 first (3-seed reserved for the eventual submission), then Phase A decision-harness retests of the stale verdicts.

## Results

![[v9_curves_grid.png]]
> *v9 per-dataset learning curves (s42): the searched dilated backbone.*

Searched dilated **+52.4** vs the fixed TCN-2d **+59.2**: the **search is NET-NEGATIVE** on the encoded datasets, mis-picking depth in both directions (Language D=7 -> 85.3 vs fixed D=6 88.2; Sudoku D=8 -> 75.8 vs fixed D=6 88.1). Its shallow picks on image-like data were harmless or good. Free retest: macro-verification fired 13 times usefully; the depth cap D=8 bound on several datasets.

## Verdict / carried forward

The search hurts where the data is encoded. This directly motivates v10's **default-incumbent rule** (start from the validated default D=6; a deviation must significantly beat it) and dropping width search entirely. The fingerprint then routes encoded data away from the dilated family anyway.
