## What was done

A queue of budget-scaled extensions on top of v10, in decided order: random-arm verify first, then additional architectures + ensemble + verified width-search, THEN the budget ladder (so the long rungs exercise the new capabilities). All running/queued via `dev/run_extensions_sweep.sh`.

- **Random-arm verification (DONE 2026-06-15).** The last unverified adoption now re-trains the best random arch at a longer horizon and adopts only if it still beats the incumbent, mirroring the depth search. Validating on Sudoku+Chesseract s1337 (should recover the Sudoku -12 mirage, keep the Chesseract attention win).
- **Architecture-family gauntlet (queued).** `baselines/arch_probe/`: fixed arch per family on {Chesseract, Sudoku, Language, CIFARTile}: **attn** (SpatialSelfAttn2D, the board lead), **recur** (RowBiLSTM, the v7 Language cracker), **modern** (Conv7+SEConv3+ResNeXt, ConvNeXt-ish), all from existing vocab ops. Families that beat tcn2d/conv become gated candidates admitted at >=4h.
- **Long-budget ensemble probe (queued).** `baselines/ensemble_probe/`: conv+tcn2d+tcn1d logit-average on {Chesseract, Sudoku}; tests whether a **cross-family** ensemble beats the single best at the same budget (E1 showed ensembles are conditionally, not universally, useful). The "what to do with surplus time at 8h" answer.
- **Verified width-search (DONE + queued).** `WIDTH_SEARCH=1` env-gated stage: default-incumbent W=48 vs {32,64}, short-train + re-train verify before adopt; the systematic version of "search width again" (width-prune cratered in v9 only because it had no verification).
- **Per-stage macro search (queued).** Informed by [[2022 - BLOX Macro NAS Benchmark]]: heterogeneous-block nets Pareto-dominate uniform stacks (which v10 builds), but proxy block-quality scores are unreliable, so a real macro search must be **verify-heavy**. Decision: do NOT port the full blockwise BLOX/DONNA/LANA machinery (needs a pre-trained teacher); instead a **verified per-stage op search** (3 contiguous stages, greedy per-stage swap, adopt only if it verifies above the uniform incumbent). Candidate ops are evidence-chosen from the gauntlet.

## Why (motivation; what changed from v10)

The TCN excursion's meta-lesson: one different architecture family was worth +11, so screening more families is high-prior, aimed at the encoded datasets where the fingerprint says wins are thinnest. The random-arm bug also had to be closed.

## Tested

Seed 42, 2h each (gauntlet, ensemble, width-search are isolated; macro-probe always trains the tested thing on all 13). The **budget ladder comes last** (0.5-8h), only after these exist, so the long rungs are informative.

**Headline: v10 has almost no architectural headroom left.** Exactly one dataset improves under any architectural change, every time: **Chesseract**. Per test:

| experiment | what it tested | result |
|---|---|---|
| **arch gauntlet** (attn / recur / modern, fixed) | whole alternative backbones | win ONLY on Chesseract (+0.4 to +1.6); crater elsewhere (CIFARTile -20 to -28, Language -7 to -12) |
| **ensemble** (conv+tcn2d+tcn1d logit-avg, ungated) | cross-family ensemble | Chesseract +1.4, Sudoku **-16.0** (averages a strong model with weak ones) |
| **width search** (verified W=48 vs 32/64) | add width to the structural search | net no-op (Chesseract +1.2, rest noise); verified search correctly keeps the default |
| **macro (forced, ungated)** | per-stage heterogeneous ops, no gate | Chesseract **+5.94** (4x any fixed alt), Windspeed +0.65; everything else loses, Sudoku **-33.6** |

The per-stage macro search captures Chesseract ~4x better than any fixed alternative (+5.94 vs +1.6), so heterogeneity *per stage* finds something whole-backbone swaps cannot.

## Verdict / carried forward

**v11 = v10 + one gated, verified, per-stage macro-attention search, replacing the fragile random arm** (lean candidate set, verify-before-adopt as the gate, budget >=4h). Keep the cross-family ensemble but properly gated (member-quality bar + keep-if-verified-better); it was only tested naive/n=2. Reject width search (no-op) and extra fixed families in the gate. The in-depth per-stage macro search (RUNNING, `dev/macro_search_indepth.py`, 16 datasets, 8 ops, verified) produces the stage x op utility map that fixes the final candidate set; this note gets the map when it lands ~2026-06-20.
