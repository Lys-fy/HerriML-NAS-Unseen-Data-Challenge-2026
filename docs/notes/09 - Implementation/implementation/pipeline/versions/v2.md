# v2 - gap-penalised probe, symmetric threshold

> **Status:** swept, net negative | **Dates:** 2026-05 | **Code dir:** `baselines/v2` | **Total adj:** net **-4.14** vs EGNAS-full | **Deep-dive:** [[Pipeline v1-v7 - Aug Probe]]

## What was done

Aug-safety probe with a **gap-penalised score** to defeat the v1 over-fit artefact: `score = val - 0.3*max(0, train - val)`, turn aug **OFF iff Δscore < -0.5 pp** (symmetric threshold).

## Why (motivation; what changed from v1)

v1's raw-val rule was fooled by aug-off over-fitting faster at K=4. Penalising the train-val gap was meant to discount that misleadingly-high aug-off val.

## Tested

Full sweep, 13 datasets x 3 seeds, paired against the EGNAS-full baseline (+35.51 +/- 3.07).

## Results

Net **-4.14** vs EGNAS-full. Language was fixed correctly (+5, OFF on all seeds), but false-OFF craters appeared elsewhere: AddNIST s2024 and MultNIST s42+s1337 (-4.94 / -3.46).

## Verdict / carried forward

A symmetric +/-0.5 pp threshold sits deep inside the ~+/-6 pp K=4 noise band, so borderline datasets coin-flip into a false-OFF. Carried forward: an **asymmetric threshold** that only flips OFF on a strong signal (v3).
